About this tool

        
A focused bridge from source data to Hubverse.

        
Hubverse model output uses one row per unique prediction. This standalone tool turns ordinary Excel, CSV, TSV, JSON, or pasted data into that structure and catches common formatting problems before submission.

      


      

        

          
What each field means

          

            
reference_date
The round or forecast reference date used by many hubs. The exact date field comes from the selected hub. Dates are exported in ISO YYYY-MM-DD format.

            
location
The hub's identifier for the geographic unit, such as a FIPS code or a custom location ID. Values are kept as text so leading zeros are preserved.

            
output_type + output_type_id
The representation and row identifier: for example, quantile with probability level 0.25, or sample with a sample ID.

            
value
The prediction. Its datatype and limits come from the matching target and output-type block in tasks.json; a count target does not automatically mean quantile values must be integers.

            
target
A hub task ID identifying the outcome. Assign one target to all rows, map target values from a source column, or assign targets to inclusive row ranges.

Use the hub's exact setup

          
The selector includes the 30 public hubs in the Hubverse directory, grouped as active, training, model development, and archival entries (directory updated 31 August 2026). Private directory entries are deliberately omitted.

          
If a hub provides hub-config/tasks.json, load it during mapping. The tool reads model-task groups, target IDs, task-ID fields, accepted output types, output-type IDs, and target-specific value rules, then adjusts the form and checks.

          
Only fields required for the selected hub are exported. Unmapped source columns are removed automatically, and all recognized dates are written as ISO YYYY-MM-DD.

          
A hub can still define additional rules that only its official validation workflow knows. Treat this browser check as preparation—not a replacement for final hub validation.

All parsing, cleaning, checking, and file creation happen inside this browser tab. The HTML has no analytics, server calls, or external code dependencies.
