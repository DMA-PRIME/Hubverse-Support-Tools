Field-by-field guide

What goes into model metadata?

A metadata file identifies a model, its contributors, methods, and reuse terms. The exact fields depend on the hub you select.

Selected hub

Fields in this schema

Required fields must be present. Optional fields are omitted from the downloaded YAML when left blank.

File and filename rules

  • YAML format

    The download uses .yml, safely quotes field names and text values, and preserves the field order defined by the hub schema.

  • Exact model identifier

    The filename is model_id.yml when the schema uses model_id; otherwise it is team_abbr-model_abbr.yml.

  • Correct destination

    Place the file in the hub repository’s model-metadata/ directory when preparing the submission.

What validation covers

The builder checks required fields, types, enumerated choices, character limits, patterns, email and URI formats, nested objects, arrays, and the Hubverse filename convention.

Some hubs run extra submission checks that are not written in their JSON schema. A green result means “valid against this schema,” while the hub’s own continuous-integration checks remain authoritative.
